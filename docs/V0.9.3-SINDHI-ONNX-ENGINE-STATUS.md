# KeyPop v0.9.3 — Sindhi offline neural translation foundation (experimental)

## Why earlier versions could not translate Sindhi
KeyPop 0.9.x uses Google ML Kit on-device translation, which supports Urdu but not Sindhi. The built-in phrasebook provides approximately 30 fixed phrases, not unrestricted machine translation. Gboard has its own Google Translate integration that third-party apps cannot simply embed.

## Verified third-party IndicTrans2 ONNX sources
IndicTrans2 supports Sindhi (Arabic script, snd_Arab), Urdu (urd_Arab), and English (eng_Latn). Public MIT-labelled ONNX INT8 exports include:
- English to Sindhi: hari31416/indictrans2-en-indic-dist-200M-ONNX-int8, revision 1eaa43a, approximately 318 MB
- Sindhi to English: hari31416/indictrans2-indic-en-dist-200M-ONNX-int8, revision a7ecdc0, approximately 270 MB

The APK never bundles these large weights. Models are downloaded to app-private storage only after the user confirms the transfer. They are not system-level Google Translate offline packs.

Sources: https://github.com/AI4Bharat/IndicTrans2 and https://huggingface.co/hari31416/indictrans2-en-indic-dist-200M-ONNX-int8

## What this development branch actually implements
- Fixed HTTPS model URLs with revision pins, twenty required encoder/decoder/tokenizer files across the two translation directions.
- Sequential resumable file downloads on a background thread with per-file byte progress; per-download consent, space checks, delete, and installed-file status.
- SHA-256 verification against publisher-linked file hashes when the hosting server supplies them, and separate local digest receipts. A local digest is never asserted to prove publisher authenticity.
- Android ONNX Runtime 1.31.1 and background encoder-model loading diagnostics.
- A visible experimental section in Language Pack Manager explicitly warning that model files alone do not translate sentences.
- Unit tests for file manifests and URLs; the existing emulator smoke test remains a release gate.
- Publishing deliberately disabled for this incomplete prototype.

## Required engineering before functional offline Sindhi
1. Android-compatible tokenizer for the published source and target tokenizers.
2. IndicTrans2 language tag handling, Sindhi Perso-Arabic script normalization, IndicProcessor preprocessing/postprocessing.
3. Encoder and autoregressive decoder inference with attention masks, KV caches, EOS handling, token bounds, resource cleanup and memory safeguards.
4. End-to-end Sindhi-English sentence accuracy tests and Unicode/RTL rendering checks.
5. Urdu-Sindhi routing (separate Indic-Indic model or validated English pivot).
6. Airplane-mode, mobile-data/Wi-Fi, download integrity, memory, emulator and physical-device tests.
7. Separate offline speech-recognition models for unrestricted Sindhi voice input.

## Do not call this finished
Downloading two model bundles is not the same as a complete translation engine. Until tokenization, generation, quality and offline-device tests are implemented and pass, the existing phrasebook and optional provider remain the only Sindhi translation paths.

The Gboard-like keyboard translation panel can later use this engine for editable source text, target selection, preview, insert and send, without transmitting typed messages to a remote service.
