# KeyPop v0.9.1 preview — launch, downloads, and Sindhi clarification

## Changes
- First run now shows keyboard activation and a choice to manage language packs; the app does not automatically navigate to another Activity and obscure its launcher.
- English and Urdu model downloads are user-triggered. The Wi-Fi-only checkbox defaults **off**, permitting mobile data, and download errors include actionable guidance.
- The Language Pack Manager now explicitly shows Sindhi and its existing basic phrasebook. There is no downloadable ML Kit full Sindhi translator. A button opens the separately installed official Google Translate app, or the Play Store listing, so the user can select Sindhi and its offline pack there.
- **Important:** Google Translate offline language assets are not accessible to KeyPop. This is an external workaround, not full Sindhi translation implemented in KeyPop.
- Android keyboard settings remain required for selecting the IME; a launcher icon is not itself a typing surface.
- The debug package suffix is changed to .previewv091. It installs beside the previous preview and has a distinct system keyboard label, avoiding debug keystore signature conflicts across build runners.

## Validation limitations
GitHub CI runs unit tests, lint, and APK assembly. A real phone startup, keyboard selection, and downloads over Wi-Fi/mobile data must still be tested. A build passing is **not** evidence of successful device startup or network model downloads.

## Future full Sindhi implementation
License and integrate a genuine compatible on-device translation model, including tokenizer/inference runtime, verified model integrity, availability, memory/storage requirements, progress reporting, and quality tests. Google Translate offline model files must not be treated as ML Kit models.
