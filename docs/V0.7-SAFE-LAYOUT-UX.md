# KeyPop v0.7 — Familiar ergonomics and safe resizing

**Status: Android alpha — not competitor parity certified.** This iteration responds to physical-device complaints about navigation-bar overlap, lack of direct resizing and ambiguous keyboard controls.

## Changed
- Android input view listens for navigation-bar insets and reserves bottom safe padding. The IME window sets an opaque navigation-bar color so the last row is distinguishable from Android system navigation.
- A clearly labeled toolbar: **Tools | Resize | Clips | Emoji | Settings**. Uncommon features are grouped into the Tools panel and remain available. No accidental theme-cycle shortcut.
- Direct **Size & Position** panel: top drag-to-resize handle; sliders for key height (36–90dp), keyboard width (65–100%) and bottom lift (0–96dp); floating placement controls; Reset and Done.
- Theme gallery navigation is preview-only. Appearance changes only after **Apply selected theme**. Explicit color selection remains an intentional action.
- Six original layout presets including Material Familiar (Gboard-inspired), Swift Flow (SwiftKey-inspired), One UI Grid (Samsung-inspired), Gesture Minimal (Fleksy-inspired), Faceted Comfort (Typewise-inspired) and KeyPop Custom. Each changes key geometry, number row, spacing and footer composition; selections are preview-first and applied only after confirmation.
- Presets and sizing settings included in user-exported design preferences; personal clips/credentials excluded.

## Constraints
The presets approximate familiar ergonomic workflows, not licensed copies. The original KeyPop keyboard code and designs are retained. Google/Microsoft/Samsung/etc. do not endorse or provide these presets.

Must still be tested on real devices with three-button, two-button and gesture navigation, including phones with display cutouts and OEM edge-to-edge behavior. Unit tests alone do not verify OEM render behavior.

## Test protocol
1. Open v0.7 on portrait gesture-navigation and three-button phones. Verify Space, Enter, Backspace are visibly above system navigation.
2. Press Resize, drag handle and move height/width/bottom offset. Tap Done, reopen keyboard and verify saved values.
3. Open Tools, switch features, verify theme, keyboardPreset, customAccent and spacing stay constant.
4. Browse themes without applying and confirm active theme unchanged. Tap Apply and confirm it changes only then.
5. Preview familiar layout presets, apply one, inspect actual keys, toolbar and number row; return to KeyPop Custom.
6. Confirm original 15 themes, Urdu/Sindhi characters, clipboard, writing, translation and Autofill remain available.
7. Run GitHub unit tests, lint and debug builds. Do not equate CI success with top-keyboard parity.
