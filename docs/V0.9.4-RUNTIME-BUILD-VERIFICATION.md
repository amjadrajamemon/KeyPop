# KeyPop 0.9.4 Android runtime build verification

Why previous versions failed CI: v0.9.3 compiled and passed lint/unit tests, but Android 35 Google APIs emulator UIAutomator was blocked by the system-level dialog "Pixel Launcher isn't responding", not a proven KeyPop crash.

Changes: use an AOSP Android 35 emulator, install an AndroidJUnit4 instrumentation test APK, and inspect the real views of KeyPopHomeActivity, KeyPopModelManagerActivity, and MainActivity with ActivityScenario from inside the application. Also confirm AetherImeService registration through Android InputMethodManager.

CI must additionally cold-launch KeyPop, enable/select its IME, verify the installed package, inspect logcat for fatal errors and attach forensic screenshots/logs. Publishing ARM64 and Universal preview APKs is gated by successful Gradle, instrumentation and emulator jobs.

Version 0.9.4 uses a unique .previewv094 debug application ID and displays separate labels.

TRANSLATION LIMITATION: IndicTrans2 ONNX files can be downloaded experimentally and an encoder can be probed, but full neural Sindhi translation, tokenizer/decoder loop, offline Sindhi voice recognition, phone-specific model downloads and pixel-by-pixel Gboard parity remain unverified and must not be represented as complete.
